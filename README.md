# 100 Days of Python Projects

My daily Python learning journal and project portfolio. Each day contains the code I wrote while learning, followed by an original project as the course becomes more independent.

## Structure

```text
days/
	day-01/
	day-02/
	...
	day-16/
```

Every day should contain the code, notes, and project work for that day. Course explanations are studied on Udemy; this repository contains my implementations and learning record.

Project-specific documentation lives beside each project. Broader concepts and reflections are collected in [notes](notes), with one file per day through Day 16.

For every new day, follow the [daily workflow](DAILY_CHECKLIST.md). It explains what to create, where to write learning notes, how to test the project, and what to check before committing.

## Daily project standard

Each new project should have:

1. A short problem statement and feature list.
2. A runnable entry point such as `main.py`.
3. Input validation and useful error messages.
4. A README with setup and usage instructions.
5. Tests when the logic is worth testing.
6. A short note about what I learned.

## Git workflow

Use one commit for each meaningful step:

```text
Day 16: start project
Day 16: implement core features
Day 16: add validation and tests
Day 16: document usage
```

The strongest projects can later become separate GitHub repositories with their own focused README, screenshots, tests, and release history.
